Walking the study as a participant 以被试身份走完整场实验

被试实际坐过的九个阶段、二十一个界面,每一步都是脚本在真实浏览器里 跑出来的截图,配上那一步的实测结果——屏幕上有没有钟、日志落了哪些事件。 材料是一份真实的 EB-1A 申请案卷。

The nine phases and twenty-one screens a participant actually sits through. Every screenshot is captured by script in a real browser, paired with what was measurably true at that moment — whether a clock was on screen, which events reached the log. The material is a real EB-1A filing.

阶段顺序由服务端强制:被试不提交就到不了拷问段,主试也跳不过任何一段。 只有主试能推进,被试从头到尾没有「下一步」这个按钮。每张图下面的灰条是那一刻从 页面和日志里读出来的事实,不是我写的说明。

Phase order is enforced on the server: the probe is unreachable without a submission, and no phase can be skipped. Only the moderator advances; the participant never has a "next" button. The grey strip under each screenshot is read off the live page and the live event log, not written by hand.

What the walkthrough found这一趟查出什么

走了两遍——先用占位材料,再用这份真实案卷。二十个缺陷,其中九个会在 当时毫无异常的情况下损坏数据。下面按后果分组,只列会影响结论的。

Two passes: once on placeholder material, once on this real filing. Twenty defects, nine of which would have damaged the data with nothing looking wrong at the time. Grouped below by what they would have cost.

初稿基线每次重新生成都被覆盖/The baseline draft was overwritten on every regenerationfixed

「被试改了什么」全部对着初稿算。而那个文件每次生成都被重写, 进入核验段还会自动再生成一次——基线常常在需要它的阶段开始之前就没了。当时什么 都看不出来:请求内部顺序仍然正确,每一稿仍然记了哈希,integrity 仍然报告 「初稿与终稿俱在,哈希吻合」。

Every measure of what the participant changed is computed against the first draft. That file was rewritten on every generation — and entering verification regenerates automatically, so the baseline was routinely gone before the phase that needs it began. Nothing surfaced at the time.

6 draft_snapshot events, 6 different sha256 on disk: the last one — 2 sentences, 280 chars the actual first draft — 11 sentences, 1373 chars — gone

编辑日志和答案卷用两套句子编号/The edit log and the answer key named sentences differentlyfixed

编辑器自己造句 id 而不是沿用服务端的。血缘记录得完整而无用: 没法和快照或拷问段对上,于是「被试改的是哪条植入句」——核验段的核心测量—— 根本答不出来。

The editor minted its own ids instead of keeping the server's. The lineage recorded splits perfectly and uselessly: it could not be joined to the snapshot or the probe, so the phase's central measure had no answer.

before snapshot: s1_0 s1_1 s2_0 … edit log: s_mt29wwt3_a … overlap 0 of 10 after affected_sent_ids: ['s1_0'] overlap 11 of 11

被试自己写的句子可能继承一条植入错误/A participant's own sentence could inherit a planted errorfixed

短句之间共有引证方括号和常用词,相似度会被推高。被试在第一段 键入的九个词,对两段之外一条原封未动、自身以 1.0 匹配的句子得分 0.43,落进「重写」频段,于是继承了它的 id 和 planted_id。拷问段随后 会拿被试自己写的句子提问,而答案卷说它是植入错误。阈值是预注册的,没动; 加的是一条消歧规则。

Similarity over character bigrams runs high on short strings sharing citation brackets. A typed sentence scored inside the "rewritten" band against a sentence that was itself still present, untouched, matching at 1.0 — and inherited its id and its planted_id. The pre-registered thresholds were left alone; a disambiguation rule was added.

typed "Separately, the record supports this." → 0.4317 vs s3_1 s3_1 itself, elsewhere in the letter → 1.0000 a sentence matching at 1.0 cannot also have been split

每条植入句的正确版本差点被发到浏览器/The correct version of every planted sentence nearly shippedfixed

为了让植入可重跑,需要在句子旁边留一份生成器的原话。那个字段 会随信一起发出去。不是关于答案的线索,就是答案本身,和被植入的版本躺在同一个响应里, 六条一次全给。根因是守卫方向反了:服务端列的是「要剥掉哪些字段」,于是以后每加一个 服务端字段默认都是泄露。现在改成列「允许发出去哪些」。

Making the planting re-runnable meant keeping the generator's original wording beside the planted text — and that field would have gone out with the letter. Not a hint about the answer: the answer, next to the planted version, for all six at once. The guard listed fields to strip, so every new field was public by default. It now lists what may be sent.

刷新一次页面,整个组织段静默清空/A page reload silently erased the whole organization phasefixed

树只活在浏览器内存里。刷新、崩溃、误按后退,所有分论点回到 「待审」,改名和移动全部消失,下一次生成用的是机器最初的提案。信照样渲染,阶段照样 推进,日志里每一步操作都还在。在核验段这比丢工作更糟:被试正在核验的那封信, 被当场用一棵他没整理过的树重建了。

The working tree lived only in the browser. A refresh put every sub-argument back to "proposed" and undid every rename and move, and the next generation ran against the machine's original proposal. The letter still rendered, the phase still advanced, the log still held every operation. In verification it was worse than lost work.

before reload 2 accepted · 1 renamed · 1 moved after reload 6 proposed · 0 accepted · letter regenerated from the pristine tree

真实材料下,拷问段的「看原文」按钮根本不出现/On real material the probe's source button never appearedfixed

引证解析器的 id 字符类不含连字符。占位包的编号是 B2、 C1,而真实申请书按 C-1、G-5 编号——解析失败, 按钮就不渲染。没有报错,只是没有。于是每一场的每一题 source_opened 都是 false,而「作答前有没有查原文」正是本研究要收的 测量之一。这条只有真实材料能暴露。

The parser's id class allowed no hyphen. The placeholder bundle numbered exhibits B2, C1; a real filing numbers them C-1, G-5. Parsing failed, the button did not render, nothing errored. source_opened would have been false for every item in every session — and whether they checked is one of the measures the study exists to collect. Only real material could surface this.

/\[Exhibit\s+([A-Za-z0-9]+),\s*p\.(\d+)/ "[Exhibit C-1, p.2]" → null /\[Exhibit\s+([A-Za-z0-9][A-Za-z0-9-]*),\s*p\.\s*(\d+)/ → { exhibit: "C-1", page: 2 }

一场完整的场次因为上一个被试而被判无效/A complete session was invalidated by the previous participantfixed

崩溃镜像按浏览器来源存,不按场次。实验室一台机器连着跑 24 个人, 上一个被试没发出去的队列会被下一个人的 logger 恢复,序号也跨场继续—— 于是下一场从 108 开始,服务端记下一个 107 条的缺口。

The crash mirror was keyed by origin, not by session. On one lab machine running 24 participants in sequence, one participant's unsent queue was restored into the next one's logger and the sequence continued across the boundary.

seq_gaps: [[1, 107]] seq_continuity FAIL 107 of 181 client events never arrived (59.1%) verdict: invalid ← a session in which nothing was lost

选中第一张证据卡就整页白屏/Selecting the first evidence card white-screened everythingfixed

一个面板直接读了新材料包没有的字段容器。React 卸载了整棵树—— 顶栏、证据、结构、信件一起消失,而且当时没有 error boundary,主试看到的白页和浏览器 崩溃无法区分。两半都修了:面板不再假设容器存在,并加了边界,捕获后写进日志并提示 「请告知主试」。

A panel read straight through a container the new bundle did not have. React unmounted the whole tree, and there was no error boundary, so a moderator would see a blank page indistinguishable from a crash. Both halves are fixed.

live 生成每个服务进程只成功一次/Live generation worked once per server processfixed

provider 缓存了一个 HTTP 客户端,绑在创建它的事件循环上,而桥接 每次出栈都会关掉自己的循环。第一个按下重新生成的被试拿到了 live 文本;之后这个进程里 每一次请求、每一场次,都是 503。新鲜进程里单调一次完全正常——所以直接测试测不出来, 是部署级彩排跑起来才现形。

The provider caches one HTTP client bound to the loop that created it, and the bridge closed its loop on the way out. The first participant to press Regenerate got live text; every request after that, in that process, for every session, got a 503. One call in a fresh process looks healthy — which is why the deployment rehearsal caught it and a direct test did not.

准备段和讲解段能读到真实案件/The real case was readable during the briefingfixed

那两段渲染了完整工作区并加载了真实 exhibit,顶栏还挂着核验段的 标题。被试可以在没人计时、没人观察的时候把即将被测的案子读一遍。现在服务端在这两段 也只发练习包,前端就算问也拿不到。

Both phases rendered the full workspace with the real exhibits loaded, under the verification phase's heading — the case they were about to be measured on, readable unobserved and untimed. The server now serves the practice bundle there too.

练习段显示的是正式案件的法条和申请人姓名/Practice displayed the real criterion and petitionerfixed

法条、条号、案件名是界面翻译文件里的固定字符串。练习段本该是 另一个法条——它却在练习材料上方显示着正式案件的法条和真实申请人姓名。三者现在都 来自材料包。

The criterion, the statute and the case name were fixed strings in the translation file. Practice is a different criterion on purpose, and it was showing the real one, with the real petitioner's name, above practice material. All three now come from the bundle.

其余/The restfixed

拷问会问到同一句两次;首次刷新之后日志丢失对连续性检查不可见; 按放大镜会多记一次并未发生的卡片点击;重构后信过期却无提示;提交没有二次确认; 首次生成前按钮写着「重新生成」;切走标签页后阶段最多滞后一分钟; 事件量检查拿 n=2 的基线算 z 分数,把第一场真实场次标成 +51σ。

The probe could ask the same sentence twice; log loss became invisible after the first reload; pressing the magnifier logged a card click that never happened; restructuring left the letter stale with no cue; submitting had no confirmation; the generate button read "Regenerate" before anything existed; switching tabs left the phase up to a minute behind; the volume check computed a z-score against a two-session baseline and flagged the first real session at +51σ.

我判断错的地方/Where I was wrong

五处我当成缺陷的其实不是。服务端给每条事件盖自己的到达时间, 看着像时钟损坏,其实客户端原时间就保存在旁边。生成失败的提示是有的,我在信件面板里找, 它渲染在屏幕底部。过期横幅也在,坏的是触发它的判据。软锁确实拦得住——我的脚本点击 绕过了真实指针必须经过的命中测试。分论点标题被截断是我的窗口太窄,不是布局问题—— 不过实验机若是那个宽度,十条标题会全被截掉,而没人会注意到。

Five things I called defects were not. The server stamps its own arrival time on every event, which reads as clock corruption until you notice the client's own timestamp is preserved beside it. The generation-failure toast exists — it renders at the foot of the screen, not in the letter panel. The stale banner exists too; the bug was in what triggered it. The soft lock does block everything, and my test only got through because a scripted click skips the hit test a real pointer cannot. And the truncated titles were my narrow window — though a lab machine at that width would truncate all ten, and nobody would notice.

Still open仍待决定

选树规则无法被一个称职的生成器满足/The tree-selection rule cannot be satisfied by a competent generatorneeds a decision

预注册规则要求剔除「挂进本法条的跨法条证据少于两条」的候选树—— 干扰节点是那几项克制检查得以成立的前提。五棵候选各只放了一条,而且是同一条: 一份被所有候选读作「评审者本人资历」的简历,这个放法站得住。他自己的论文五棵全部 正确排除。换种子只会重复同样正确的判断。规则预设生成器会误放证据,而这一个不会。 干扰节点必须被设计进去,那是对预注册的修订,不是改脚本。 当前选定的树标为 provisional,未通过筛除的那一轮如实存档。

The rule discards any candidate hanging fewer than two cross-criterion items under the criterion — the distractor node is what makes the restraint checks meaningful. All five placed exactly one, and the same one: a biography every candidate read as the judge's own credentials, which is defensible. All five correctly excluded his own article. New seeds would repeat the same correct judgement. The rule presumes a generator that misfiles evidence; this one does not. The distractor has to be introduced deliberately, which is an amendment to the pre-registration, not a change to a script.

植入句尚未经移民律师过目/The planted sentences have not been read by an attorneycleared for use

已放行使用,流程不再卡,而这与「已审阅」分开记录: cleared_for_use: true 与 reviewed_by_attorney: false。 合并两者等于让「能跑」冒充「这些确实是从业者会认作错误的东西」,而后者是因变量的 刻度尺。目前两条夸大分别是 2.5 倍和 5 倍,比设计文档建议的 1.5–2 倍激进—— 这正是四场 pilot 该定的事。

Cleared so the pipeline is not blocked, recorded separately from review. Collapsing the two would let "it runs" stand in for "a practitioner would call these errors", and the second is the scale the dependent variable is measured on. Two of the overstatements are currently 2.5× and 5× against a suggested 1.5–2× — exactly what four pilot sessions exist to settle.

克制审计需要一个没写这些代码的人/The restraint audit needs someone who did not write the codenot startable by me

验收流程要求五项克制检查由未参与实现的人对着红线独立过一遍。 这是进 pilot 前的最后一道闸,我不能是那个人。

The acceptance procedure requires five restraint checks to be walked independently, against the red lines, by a person who did not implement them. It is the last gate before pilot and I cannot be that person.

未阻塞的其余项/Unblocked remainder

人工清单还剩三项没走(键盘导航、TEST 徽章对拍、中文场次); 三栏布局没有最小宽度保护,约 1280px 以下每条分论点标题都会截断,而被试的任务恰恰是 读和重组这些标题;目前只建了一个法条的材料包;条件 B 仍是或有项; 除笔记本外尚未部署。

Three items on the manual checklist have not been walked (keyboard navigation, the test-badge comparison, a Chinese-language session); the three-column layout has no minimum-width guard and below roughly 1280 px every sub-argument title truncates while the participant's whole task is reading and reorganising them; only one criterion has been built; condition B remains optional; nothing is deployed beyond a laptop.

截图由 backend/scripts/capture_flow.py 在真实浏览器里 脚本化生成,每张图下的实测结果同时从页面和事件日志读出。界面改动后重跑即可, 论文配图用同一套。材料包留在本地不进版本库:里面每一份 exhibit 都已公开,但一个 具名个人的案卷汇集到一处是另一回事,而仓库是公开的。

Screenshots captured by backend/scripts/capture_flow.py in a real browser; the results beneath each are read from the live page and the live event log at the same moment. Re-runnable when the interface changes, and the same figures serve the paper. The material bundle is held locally and kept out of version control: every exhibit in it is published, but a named individual's case assembled in one place is a different thing, and the repository is public.
